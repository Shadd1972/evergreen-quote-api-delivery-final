## How I'll use this register

I re-read the register at each 10:00 check-in and update it at the 16:00 wrap, and again after each inject, since an inject is the most likely moment for a new risk or a changed likelihood. It lives in the repo, so the sponsor and any reviewer can see the current version on GitHub at any time. Any row that hits its trigger goes into that day's status update by number (e.g., "R3 triggered"), so the sponsor never has to read the full table to know what changed.
